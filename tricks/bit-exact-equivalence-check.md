# 改推理前处理时，用「下沉到最小单元 + 真实数据」验逐位一致

**场景**：为了省 CPU↔GPU 搬运，把 `prepare_input_tensor` 从「CPU 预处理整窗」改成「GPU 上按 tile 处理」。直觉上等价，实测输出 PSNR 只有 37 dB。

## 三步定位（总耗时 < 10 s，不加载模型）
1. **同路径重跑**：证明流水线是否确定。`A vs A: max|Δ|=0.0` → 确定性没问题，差异是改动引入的。
2. **单点 A/B**：只切一个开关（`FLASHVSR_GPU_PREPARE=0/1`），其余完全相同。
3. **下沉到最小单元**：把改动的函数单独拎出来，喂**同一份真实数据**（真视频帧，不要用随机数——随机数会掩盖 ULP 级偏差），逐位比。
   ```
   plot: (1,3,9,256,256) vs (1,3,9,256,256)  max_d=7.812e-03  mean=1.325e-08
   ```
   `7.812e-03 = 2^-7` 是 bf16 的 ULP → 说明输入在 cast 前只差 1 个 float32 ULP。

## 关键结论（可复用）
- **GPU 的 float32 除法与 CPU 差 1 ULP**（一半元素）。`x_uint8 / 255` 在 GPU 上做，再进 fp8/MXFP8 流水线，会被 block scale 放大成肉眼可见级别的输出差异。
- 想逐位一致：`uint8 → float` 的归一化放在 **CPU** 上做（哪怕只有切片），或者干脆别把归一化挪到 GPU。
- 只有当**输入 float32 完全相同**时，GPU 版插值 + bf16 cast + `*2-1` 才能与节点版逐位一致（已验证 0/1769472）。
